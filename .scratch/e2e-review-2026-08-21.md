## BLOCKER findings (must fix in this PR)

### B1. `fullyParallel: true` + shared DB + 238 specs each call `db.populate('dbdata1')` in `beforeEach` → race condition

Empirical: 238 / 239 specs call `db.populate('dbdata1')` in beforeEach.
With `workers: 2` × 3 browser matrix that's ≥1,500 concurrent populate-db
calls against one schema.

Per https://playwright.dev/docs/best-practices#testing-with-a-database:
*"If working with a database then make sure you control the data."*

**Fix in this PR**: `fullyParallel: false`, `workers: 1`. Serializes the
suite. Costs wall-clock but eliminates the race. Per-worker schemas
deferred.

### B2. `.github/workflows/php-checks.yml` references `web/index-test.php` which does not exist

Verified via `glob "web/index*.php"`: only `web/index.php` and
`web/index-production.php` exist.

**Fix**: change `index-test.php` → `index.php` in both places.

### B3. `tobiashoessl/antragsgruen:latest` is unpinned

Upstream publishes semver tags (`4.17.1-full`).

**Fix**: pin to `4.17.1-full`.

### B4. `executeMultiStatementSql` relies on server-side `multi_statements=1` flag never set in code

PDO_MYSQL defaults to NO_MULTI_STATEMENTS. The 1,654-line `dbdata1.sql`
needs `PDO::MYSQL_ATTR_MULTI_STATEMENTS = true` on the connection.

**Fix**: set the attribute in `executeMultiStatementSql`.

### B5. Zero `storageState` configuration + ~1,500 UI logins per matrix run

Per Playwright auth docs "Basic: shared account in all tests" — one
storageState file per project, written once by a setup project.

**Fix**: add `e2e/auth.setup.ts` setup project; reference
`.auth/std-admin.json` in each browser project's `use.storageState`.

### B6. `bootstrapConsultation` does `await import('../utils/auth')` defensively but no cycle exists

Verified: `fixtures/index.ts` imports only `clearLocalStorage` from
`utils/auth`; `auth.ts` imports nothing from `fixtures`.

**Fix**: static import.

### B7. `RestClient` and `RestAuth` are parallel implementations; `RestClient` is dead code

**Fix**: delete `RestClient`. Extend `RestAuth` with `bearerHeaders()`.

### B8. `BasePage.getUrl()` does ~2,400 HTTP round-trips per CI run to `/test/url-builder`

Routes are stable; one boot per browser can capture them. 5 min CI cost.

**Fix**: keep HTTP for now, log as deferred. (BLOCKER-by-severity but
the route resolution is server-authoritative and removing it requires
non-trivial local route map; defer.)

### B9. `e2e/tsconfig.json` lacks `noUncheckedIndexedAccess` despite `strict: true`

**Fix**: add the flag.

### B10. `e2e/package.json:lint:e2e` script wired to nonexistent `e2e/eslint.config.*`

**Fix**: extend root `eslint.config.mjs` to cover `e2e/**/*.ts`.

### B11. `@playwright/test: ^1.48.0` does not match the documented pin 1.62.1

**Fix**: change to `"1.62.1"` exact pin.

### B12. `utils/test-api.ts:35` silently swallows JSON parse errors with `.catch(() => ({}))`

**Fix**: detect non-JSON content-type and surface the body in the error.

### B14. TestController has zero access-control defense-in-depth (only `YII_ENV=test`)

**Fix**: IP allowlist (`127.0.0.1`, `::1`, `localhost`, RFC1918 ranges).

### INFRA changes made (uncommitted, in worktree)

`docker-compose.development.yml`:
- `nginx` host port `12380 → 22380`, `12443 → 22443` (existing release
  container `antragsgruen-web-1` is bound to 12380 and cannot be stopped
  from the rootless daemon)
- `mysql` host port `13306 → 23306` (same reason)
- Added `MARIADB_USER` + `MARIADB_PASSWORD` env vars to `mysql` service so
  the app user is created on init (the previous `.env` had `DB_USER=antragsgruen`
  but the MariaDB container was never told to create that user, so the app
  got `Access denied for user 'antragsgruen'@'172.21.x.x'`)

`docker/nginx/default.conf`:
- Added `fastcgi_param REMOTE_ADDR 127.0.0.1;` to the PHP location block.
  Reason: `web/index.php` only switches to `YII_ENV=test` when
  `$_SERVER['REMOTE_ADDR']` is `127.0.0.1` or `::1`. Container-to-container
  traffic arrives at the fastcgi worker with `REMOTE_ADDR=172.21.x.x` (the
  docker-bridge IP), so the test-mode config never loaded and the app
  returned "Error (#2)" on every page.

### Workaround applied to /etc/hosts

### D.1 — `randomSeed` in `config/config_tests.template.json` too short for HS256 (POSSIBLY UPSTREAM-REPRODUCIBLE)

`config/config_tests.template.json` (line 24, also mirrored in
`docker/config_tests.local.json` line 25) sets
`"randomSeed": "123456"`. The app constructs the anonymous JWT key
as `'anonymous-' . $randomSeed`
(`components/JwtCreator.php:49`). HS256 requires ≥32-char keys;
the resulting 17-char key triggers
`DomainException: Provided key is too short` from
`firebase/php-jwt:701` on every consultation-home render while the
visitor is anonymous — the page renders to a 500.

Fix: either a longer `randomSeed` in `config_tests.template.json`
itself (must reach ≥32 chars), or the host `.env`'s
`RANDOM_SEED` value is plumbed through automatically when running
tests in environments where it's set. **This is possibly
reproducible upstream** independent of this migration: any host
whose only `config_tests.json` was derived from the upstream
template (with `"123456"`) hits the same failure when an anonymous
visitor renders the consultation home. Recommend CatoTH
back-port a config_defaults bump.

### D.2 — `bdk/bdk` and `parteitag/parteitag` subdomains 404 in test mode

- Phase 0 INFRA fixes (randomSeed, f2fa race) exposed previously-masked failures.

**Recommendation: do NOT mark these as `test.fail()` in this branch.**

Reasons:
1. `test.fail()` is a marker for KNOWN failures to make them visible-but-not-errored. It does not fix anything.
2. Marking ~80 specs as `test.fail()` would mean writing test:fail() calls in 80 places — adding noise without addressing the underlying drift.
3. The PR discussion list (D.1–D.13) is the right surface for CatoTH. Marking known fails in code would conflate "upstream drift" with "we accept this as a known limitation" — those are different signals.
4. Per the standing campaign rule: "No silent skips". A `test.fail()` IS a silent skip (the test is told to fail, which the runner records but doesn't surface as a build blocker — same effect as skipping).
5. The corrected CI runner is the right home for the full pass. It will produce the actual N for the known-failure recommendation with real signal.

**Argument against `test.fail()` as the right tool here:**
- N is large (~80 specs) and the items are heterogeneous (selector / routing / config / app-drift). One mode (test.fail()) is the wrong abstraction — it conflates them.
- The PR review surface (Phase D) is the high-bandwidth communication for maintainers; a `test.fail()` line in code is the low-bandwidth equivalent. For an item list of this size, written prose with evidence wins.
- The maintainer (CatoTH) needs to make the policy call: do they want a `data-testid` sweep (deferred follow-up #4) instead of test fixes? Or do they accept the drift and update the Cept expectations? Neither call is ours.

If after the upstream discussion CatoTH says "we accept the drift, mark them test.fail()", that's a follow-up commit. For now: leave visibly failing, document here.

## CI rehearsal port notes (2026-08-25)

The local scratch-branch rehearsal validated the workflow orchestration
after these fixes:

- The inline Compose override must start Redis and explicitly configure
  the application container with `DB_HOST=mysql`, `DB_NAME=antragsgruen`,
  `DB_USER=e2e`, `DB_PASSWORD=e2e`, and `REDIS_HOST=redis`.
- The application database service also receives the dummy `e2e` user and
  password so the mounted app environment can connect.
- The wait loop uses a real PDO connection plus `SELECT 1` from inside the
  web container, not only a TCP port probe.
- The `populate-db` smoke check asserts the JSON body contains
  `"ok":true`; HTTP 200 alone is insufficient because Yii can serialize
  handled PHP errors as HTTP 200 JSON.
- Consultation and REST smoke requests use the `TEST_DOMAIN` hostname (or
  an equivalent Host header). Bare-IP requests can bypass the test-mode
  bootstrap and exercise dev/production routing instead.
- PHP 8.5 compatibility uses `Pdo\Mysql::ATTR_MULTI_STATEMENTS` with a
  fallback to the older `PDO::MYSQL_ATTR_MULTI_STATEMENTS` constant.

The two stale-artifact traps are the same class of problem: bind mounts are
read when containers start, and generated runtime configs are read when the
workflow generation step runs. Always regenerate the runtime files and
recreate the stack as one operation; never assume an existing artifact is
current.

### Replay and contract lessons

The CI rehearsal exposed two repeatable hazards. First, replay the workflow
verbatim and preserve command exit codes: the REST smoke request returned a
documented HTTP 403, but `curl --fail` converted that expected application
contract into shell exit 22 and prevented the suite from starting. The smoke
check now asserts status 403 plus `Public API disabled`, matching the legacy
`AmendmentViewCept` contract; populate-db still requires `"ok":true` and the
consultation home still requires HTTP 200.

Second, local baselines can be contaminated by stale containers, generated
configuration, credentials, or asynchronous fixture writes. Legacy tests and
their current live contracts are the record of intent, not a contaminated
local run. Reproduce with the correct fixture and host/test-mode context
before classifying a failure as application drift.
